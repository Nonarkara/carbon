## Review the claim, not just the sum
An inventory may add up perfectly and still omit a branch, use the wrong factor or describe a modelled quantity as measured. Independent review starts with the intended claim, boundary and evidence. ISO 14064-3 addresses validation and verification; referencing it does not certify this system or replace the applicable programme’s assurance process.

Agree who prepares, checks and approves the work. A second person should challenge the records and assumptions rather than merely repeat the analyst’s spreadsheet. Document competence, independence and conflicts relevant to the assignment. Set the assurance scope, criteria and materiality with the appropriate reviewer; do not invent a universal threshold.

## Follow one result backwards
| Layer | Reviewer question | Evidence |
|---|---|---|
| Claim | Does the wording match the actual scope and status? | Proposed disclosure |
| Total | Are included sources complete and nonduplicated? | Coverage register and reconciliation |
| Calculation | Can the arithmetic and units be reproduced? | Versioned workbook or code |
| Factor | Is this the exact applicable edition and basis? | Publisher document and factor register |
| Activity | What happened, where and when? | Bills, logs, meters and owners |

A source file hash supports traceability, not truth. A passing software test supports implementation behaviour, not field accuracy. A national benchmark can expose a discrepancy, but does not validate a parcel model. Keep these types of evidence separate.

## Use risk-based review
Select checks according to size, uncertainty and risk: missing months, large manual adjustments, unusual factor changes and boundary decisions deserve attention. Recalculate selected rows independently and reconcile the inventory to operational records. Sampling does not prove every row correct; record the sample, rationale and unresolved items.

Test controls as well as values. Who can change a factor? Are earlier exports still reproducible? Does a unit change invalidate incompatible inputs? Does a stale plot expansion disappear when its parameters change? Can an estimate be accidentally exported without its date and quality label? These are concrete checks for a system review.

## Close findings visibly
Give each finding an ID, severity, affected quantities, evidence, owner, correction and retest result. Preserve the original report if a correction has already been published. Update the revision and tell its users what changed. Material unresolved items belong in the limitations section and may constrain the claim.

Use plain status labels: **prepared estimate, internally reviewed, independently verified within the stated scope**. Use the last only when there is actual verification evidence. This platform is an unverified assessment and reference tool. An LLM may explain records or flag inconsistent language; it cannot manufacture missing measurements, independent assurance or registry approval.

## ตรวจคำกล่าวอ้าง ไม่ใช่แค่ผลบวก
บัญชีอาจบวกถูกทุกแถวแต่ลืมสาขา ใช้ตัวคูณผิด หรือบอกค่าจากแบบจำลองว่าเป็นผลวัด การตรวจอิสระเริ่มจากคำกล่าวอ้าง ขอบเขต และหลักฐาน ISO 14064-3 กล่าวถึงการตรวจความใช้ได้และทวนสอบ การอ้างถึงไม่ได้รับรองระบบนี้หรือแทนขั้นตอนประกันความเชื่อมั่นของโครงการ

ตกลงว่าใครจัดทำ ตรวจ และอนุมัติ คนที่สองควรท้าทายข้อมูลและสมมติฐาน ไม่ใช่แค่ทำตารางผู้วิเคราะห์ซ้ำ บันทึกความสามารถ ความเป็นอิสระ และผลประโยชน์ขัดกันที่เกี่ยวข้อง ตกลงขอบเขตการตรวจ เกณฑ์ และความมีสาระสำคัญกับผู้ตรวจที่เหมาะสม อย่าตั้งตัวเลขเกณฑ์สากลขึ้นเอง

## ตามผลหนึ่งตัวย้อนกลับ
| ชั้น | คำถามผู้ตรวจ | หลักฐาน |
|---|---|---|
| คำกล่าวอ้าง | ถ้อยคำตรงขอบเขตและสถานะไหม? | ร่างเปิดเผย |
| ยอดรวม | ครบและไม่ซ้ำไหม? | ทะเบียนครอบคลุมและกระทบยอด |
| คำนวณ | ทำเลขและหน่วยซ้ำได้ไหม? | สมุดงานหรือโค้ดมีรุ่น |
| ตัวคูณ | ฉบับและฐานตรงที่ต้องใช้ไหม? | เอกสารผู้เผยแพร่และทะเบียนตัวคูณ |
| กิจกรรม | เกิดอะไร ที่ไหน เมื่อไร? | บิล สมุด มิเตอร์ และเจ้าของข้อมูล |

แฮชไฟล์ช่วยตามรอย ไม่พิสูจน์ความจริง เทสต์ซอฟต์แวร์ผ่านช่วยยืนยันพฤติกรรมโค้ด ไม่ยืนยันความแม่นยำภาคสนาม เกณฑ์ประเทศช่วยเปิดความต่างได้ แต่ไม่ทวนสอบแบบจำลองแปลง แยกหลักฐานคนละชนิดไว้

## ตรวจตามความเสี่ยง
เลือกตรวจตามขนาด ความไม่แน่นอน และความเสี่ยง เดือนขาด การปรับมือขนาดใหญ่ เปลี่ยนตัวคูณผิดปกติ และข้อสรุปขอบเขตควรได้รับความสนใจ คำนวณแถวที่เลือกอย่างอิสระและเทียบข้อมูลปฏิบัติการ การสุ่มไม่ได้พิสูจน์ว่าถูกทุกแถว บันทึกตัวอย่าง เหตุผล และประเด็นค้าง

ตรวจระบบควบคุมด้วย ใครแก้ตัวคูณได้? สร้างไฟล์ส่งออกเก่าซ้ำได้ไหม? เปลี่ยนหน่วยแล้วล้างข้อมูลที่ใช้ร่วมไม่ได้หรือไม่? เปลี่ยนพารามิเตอร์แล้วค่าขยายแปลงเก่าหายหรือไม่? ส่งออกค่าประมาณโดยไม่มีวันและป้ายคุณภาพได้หรือไม่? นี่คือรายการตรวจระบบที่เป็นรูปธรรม

## ปิดข้อค้นพบให้เห็น
แต่ละประเด็นมีรหัส ความรุนแรง ปริมาณที่กระทบ หลักฐาน เจ้าของ วิธีแก้ และผลตรวจซ้ำ หากเผยแพร่แล้ว เก็บรายงานเดิม เปลี่ยนรุ่นและแจ้งผู้ใช้ว่าแก้อะไร ประเด็นสำคัญที่ไม่จบต้องอยู่ในข้อจำกัด และอาจจำกัดคำกล่าวอ้าง

ใช้ป้ายง่าย ๆ: **ค่าประมาณจัดทำแล้ว ตรวจภายในแล้ว ทวนสอบอิสระตามขอบเขตที่ระบุแล้ว** ใช้ป้ายสุดท้ายเฉพาะมีหลักฐานทวนสอบจริง แพลตฟอร์มนี้เป็นเครื่องมือประเมินและอ้างอิงที่ยังไม่ทวนสอบ LLM ช่วยอธิบายข้อมูลหรือเตือนถ้อยคำขัดกันได้ แต่สร้างผลวัดที่ขาด การทวนสอบอิสระ หรือการอนุมัติทะเบียนไม่ได้
